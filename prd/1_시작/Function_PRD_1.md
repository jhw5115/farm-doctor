# Function PRD — 과수화상병 AI 의심증상 탐지 및 대응지원 웹서비스

- 버전: 1.0
- 연계: `Common_PRD.md`
- UX 원칙: 한국어 우선, 모바일 촬영 업로드 편의, 분석 상태 명확화, 위험한 단정/처방 금지, 접근성 준수.

## 2. F-01 랜딩/서비스 소개
- 상단: 로고, 서비스 소개, 이용 방법, 대응 가이드, 로그인.
- 메인: '과수화상병 의심 증상 AI 탐지', 촬영 이미지 분석 시작 CTA.
- 3단계: 사진 업로드 → YOLO 의심 영역 탐지 → 결과 및 대응 가이드.
- 하단: 사진 분석은 확진이 아니며 공식 기관의 현장 확인이 필요할 수 있다는 고지.
- 수락: 모바일/PC 반응형, 비로그인에서도 가이드 접근 가능.

## 3. F-02 회원 및 권한
- 이메일/비밀번호 회원가입, 중복 확인, 로그인/로그아웃, 세션 만료 처리.
- 일반 사용자 기본 권한; 검토자/관리자는 서버 측 승인으로만 부여.
- 비밀번호 재설정 메일 서비스가 미구성되면 UI에 허위 발송 성공을 표시하지 않는다.
- 수락: 사용자 A는 사용자 B의 이미지, 결과, 과원 정보에 접근 불가(403/404 정책 통일).

## 4. F-03 사용자 대시보드
- 카드: 전체 분석 건수, 완료, 진행 중, 검토 필요(각각 실제 DB 집계).
- 최근 분석 5~10건, 결과 상태, 촬영 작물, 분석 시각, 상세 링크.
- 데이터 없음 상태 및 새 분석 유도.
- 수락: 새 분석 완료 시 카드와 최근 목록 갱신.

## 5. F-04 이미지 업로드 및 분석 요청
### 입력
- 이미지 1~10장 다중 업로드(설정 가능), 드래그앤드롭/파일 선택/모바일 카메라.
- JPEG/PNG/WebP, 파일당 최대 15MB(설정 가능), 미리보기, 업로드 진행률, 실패 파일별 재시도.
- 작물 종류(사과/배/기타: 실제 지원 범위로 제한), 부위(잎/가지/꽃/열매/기타), 과원 선택(선택), 촬영일(선택), 메모(선택).
- 사용자 동의: 이미지 처리 및 저장 정책, 민감 위치정보 처리 고지.

### 처리
1. POST `/api/v1/uploads/presign` → presigned PUT URL과 이미지 ID/업로드 토큰 발급.
2. 클라이언트 S3 업로드 → POST `/api/v1/uploads/complete`로 파일 검증 완료.
3. POST `/api/v1/analyses` `{image_ids:[...], crop_type, orchard_id?, notes?}`.
4. 이미지마다 job 생성, 작업 큐 전송, worker 추론; UI는 polling 또는 SSE로 상태 갱신.
5. 모델 미설정 시 작업을 허위 완료시키지 않고 `MODEL_NOT_CONFIGURED` 안내.

### 수락
- 10장 중 일부 실패해도 성공한 건의 분석은 유지.
- 동일 요청 중복 전송 방지(idempotency key), 파일 유형 위조 차단, 소유권 검증.
- 상태: 대기/분석 중/완료/실패/재시도; 새로고침 후에도 유지.

## 6. F-05 YOLO 분석 엔진
- 모델 로더는 버전/가중치 체크섬/클래스 맵 검증 후 로드.
- 전처리(이미지 회전/리사이즈), 추론, confidence/IoU 필터링, 원본 좌표로 박스 복원.
- 결과: 클래스 ID/명, 탐지 점수, 바운딩 박스, 모델 버전, 처리 시간.
- 원본/주석 이미지 저장; 오류는 작업 상태에 기록하고 UI에 안전한 메시지 출력.
- 임계값 조정은 관리자 또는 개발 설정에서만, 분석별 사용 임계값 기록.
- 다중 이미지 분석 결과는 개별 결과와 묶음 요약을 모두 제공.
- `confidence`는 모델 탐지 점수이며 실제 감염 확률이 아님을 툴팁으로 설명.

## 7. F-06 분석 결과 페이지
### 필수 UI
- 원본 이미지/탐지 영역 표시 이미지 토글, 확대, 박스 on/off.
- 결과 요약: '의심 증상 영역 탐지됨' / '모델이 탐지한 의심 영역 없음' / '분석 불가'.
- 탐지 목록: 클래스명, 탐지 점수, 영역 좌표, 모델 버전, 분석 시각.
- 결과 설명: 이미지 품질, 모델의 한계, 확진 불가 안내.
- 권고: 검토된 대응 가이드 링크, 공식 신고/문의 경로, 전문가 검토 요청(구현 시).
- 결과 공유/다운로드: PDF 또는 CSV는 선택 확장; 구현 시 개인정보 마스킹 및 접근권한 적용.

### 위험도 정책
- 임의의 `정상/확진`, `감염률 95%` 표기 금지.
- 위험도(높음/보통/낮음) 라벨은 **전문가 승인 규칙 및 검증 근거가 준비된 경우에만** 활성화; 그렇지 않으면 '검토 권장'과 탐지 상태만 표시.
- 분석 결과는 사용자에게 '공식 확진 결과가 아닙니다' 고정 고지.

## 8. F-07 대응 및 처방 지원 가이드
- 사용자의 작물 및 탐지 상태에 따라 관리자 승인된 가이드만 노출.
- 가이드 항목: 의심 시 초기 대응, 접촉/이동 주의, 기록 방법, 지역 관할 기관 문의, 현장 조사 필요성.
- 약제명·희석비·살포 일정·법적 신고 의무는 모델이 생성하지 않으며, 최신 공식 출처와 적용 지역/시점이 검증된 자료에 한해 안내.
- '처방'은 법적/전문적 처방이 아닌 **대응 지원 정보**로 명시.
- 가이드에 출처, 최종 검토일, 적용 지역, 버전, 관리자 승인 상태 표시.
- 공식 지침이 미확인/만료된 경우 구체적 방제 지시 대신 관할 기관 문의 안내.

## 9. F-08 분석 이력 및 검색
- 본인 분석만 조회, 날짜/작물/상태/과원 필터, 정렬, 페이지네이션.
- 상세 재열람, 이미지 삭제, 분석 이력 삭제(보존 정책 및 감사 로그 고려).
- 수락: DB 재시작/앱 재배포 후에도 이력 보존, 삭제 후 S3 객체 정리 작업 처리.

## 10. F-09 과원 관리
- 과원명, 작물, 지역(선택·광역 단위 권장), 메모 입력.
- 본인 과원 수정/삭제, 관련 분석 내역 연결.
- 정확한 좌표/주소는 필수 수집하지 않음.

## 11. F-10 전문가 검토
- 검토 요청: 사용자 동의 후 선택적으로 요청.
- 검토자 큐: 권한 있는 요청만 접근, 사진/AI 결과/메모 확인.
- 검토 상태: 요청됨/검토 중/검토 완료/추가 정보 필요.
- 검토 의견과 작성자, 시각, 수정 이력 보존.
- 전문가 의견도 공식 확진 여부와 구별하여 표기.

## 12. F-11 관리자
- 사용자 목록/권한/상태 관리; 최소 권한과 변경 감사 기록.
- 모델 등록: 파일/경로, 체크섬, 클래스 맵, 검증 지표, 버전, 활성/비활성, 롤백.
- 모델 미검증 시 활성화 차단 또는 명시적 내부 테스트 환경으로 한정.
- 대응 가이드 작성/검토/승인/게시/만료, 출처 URL 관리.
- 분석량, 실패율, 평균 처리 시간, 큐 적체, 모델별 사용량, 오류 로그 요약.
- 감사 로그 조회; 민감 정보 마스킹.

## 14. 디자인 요구사항
- 브랜드 임시명: `FireBlight AI` (확정 전 변경 가능).
- 차분한 농업·기술 서비스 톤: 화이트/연녹색/차콜, 경고 상태는 절제된 주황/빨강.
- 좌측 사이드바(PC): 대시보드, 새 분석, 분석 이력, 과원 관리, 대응 가이드, 계정; 역할에 따라 검토/관리자 메뉴 추가.
- 모바일: 하단 또는 접이식 탐색, 카메라 업로드 버튼 강조.
- 결과 화면은 사진을 가장 크게, 우측/하단에 탐지 요약과 안내 배치.
- 로딩/빈 상태/에러/재시도/접근 불가/모델 미설정 화면 모두 설계.
- 키보드 접근성, 이미지 대체 텍스트, 충분한 대비, 오류 메시지 명료화.

## 15. 핵심 E2E 수락 시나리오
1. 신규 사용자 가입 → 로그인 → 과원 생성 → 이미지 2장 업로드 → 분석 요청 → 완료 → 박스와 모델 버전 확인 → 이력 재조회.
2. 지원하지 않는 파일/용량 초과/변조된 파일 업로드 → 안전하게 거부.
3. 모델 파일 미설정 → 명확한 오류 및 설정 안내; 임의 탐지 결과 없음.
4. 사용자 A가 사용자 B 분석 URL 직접 접근 → 거부.
5. 추론 실패 → 실패 상태 저장, 사용자에게 재시도 경로 표시.
6. 탐지 없음 → '질병 없음' 단정 없이 안내.
7. 관리자가 가이드 승인 → 공개 노출; 만료/미승인 콘텐츠는 비공개.
8. 관리자 모델 버전 전환 → 새 작업만 새 모델 적용, 과거 결과는 당시 버전 유지.
9. AWS 재배포 후 로그인/분석 이력/S3 결과 접근 정상.
10. 보안 및 성능 검증: 이미지 1장 처리시간 p50/p95를 실제 인프라에서 측정하고 목표값은 예산·모델 크기 확정 후 설정.

## 16. 구현 우선순위
- P0: 로그인/RBAC, 업로드, PostgreSQL/S3 영속화, YOLO 실제 추론, 결과 표시, 이력, 공식 가이드, AWS HTTPS 배포.
- P1: 다중 이미지, 과원, 전문가 검토, 관리자 모델/콘텐츠 관리, 모니터링 고도화.
- P2: PDF 보고서, 통계 시각화, 알림, 지도/지역 분석(동의 및 개인정보 검토 후).

## 17. Codex에 대한 필수 지시
- 모든 화면은 실제 백엔드 API를 호출해야 하며 하드코딩 통계/가짜 탐지 결과 금지.
- 모델/데이터셋/공식 지침이 없으면 필요한 입력과 미구현 상태를 문서화하고 해당 기능을 안전하게 비활성화.
- P0 기능을 우선 완성하고 각 화면의 실제 동작을 테스트한 뒤 P1/P2 진행.
- AWS 리소스 생성 및 배포 전 비용 예상과 사용자 승인 요청.
